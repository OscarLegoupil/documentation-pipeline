# Live Copilot acceptance (separate from fixture tests)

This procedure requires an authenticated, policy-approved GitHub Copilot session in VS Code. It needs no model API credentials. The build environment did not provide that session; hand-authored fixture outputs do not certify this integration.

1. Record VS Code version, Copilot component/extension version where exposed, session host (Local or Agent Host), selected **Copilot** provider and subscription-available model, OS and `doctor` output. Do not select another provider installed in the editor. Do not enable experimental skill fork context or bypass organizational approvals.
2. Copy `tests/fixtures/web-service/` into an unrelated temporary directory whose name contains spaces and Unicode. Add `.github/copilot-instructions.md`, `.vscode/settings.json`, `docs/existing.md` and an uncommitted source edit; save hashes. Install from the release ZIP using dry-run first. Run explicit setup/doctor using the recorded local Python.
3. Open that directory in VS Code. Confirm exactly one `/generate-documentation` skill appears. Confirm ordinary unrelated coding chat does not invoke it automatically. Invoke `/generate-documentation` without scoping questions. Confirm inventory includes tests/docs/CI/infra and excludes the skill/state/output trees. Confirm the coordinator invokes engine commands and reads compact receipts rather than dumping the corpus.
4. Inspect the **actual available** native tool surface. Current docs name `runSubagent` under `agent`, but the installed host is authoritative. Request one general Copilot subagent to read its assigned packet/task/schema and write only its result path; preserve the inherited approved provider/model. Verify a real result.json exists, contains the correct snapshot/fingerprint and passes `accept`. Verify the returned chat receipt is short. Do not assume the read-only Explore agent can write artifacts.
5. If delegation/writes are unavailable, record that outcome and test bounded single-agent mode instead. One task at a time must still use the queue and acceptance checks. Open a new chat to achieve a fresh review context; a script cannot reset context. A fallback pass is **not** a native-subagent pass.
6. Interrupt after at least three accepted tasks and one outstanding task. Stop all old workers. In a new Copilot chat invoke the same slash command. Confirm explicit stopped-session recovery, accepted IDs/hashes retained, and only unfinished/invalid tasks reissued. Attempt a second simultaneous coordinator and verify recoverable refusal.
7. Let **Copilot** produce analysis, reconciled ownership, chapters, diagrams and fresh reviews. Verify `service/routes.ts → domain/orders.ts → storage/store.ts` is represented with supported call relations; imports stay distinct. The README's no-retry claim conflicts with the three-attempt source loop. `runtimeAdapter` and `/replay` dynamic handler remain unresolved. `OrderStore` is a declared logical identifier, never an invented deployed name. Both trigger declarations stay traceable. Check source citations for inputs/outputs, failure behavior and maintenance implications.
8. Change a shared source contract while a task is issued. Acceptance must reject the stale result. Rescan, confirm affected extraction and dependent content are invalidated, and finish the new snapshot. Add/delete/rename files and check manifest/coverage changes; unaffected extraction can remain reused. Confirm no target tests/build/install commands were executed.
9. Before all chapters finish, confirm an accepted subsystem's final review automatically produces `documentation-progress.docx`, labeled **Incomplete draft**, with completed/pending/blocked subsystems on its progress page. Only completed chapters and their rendered diagrams should appear. Record its hash; simulate a local exporter failure while the next chapter completes and verify that acceptance remains saved, the previous preview's hash is unchanged, and `progress_error` reports the cause. Restore the tool, resume with `next`, and confirm a new preview appears without repeated analysis/model requests. Then invoke `action=validate`, followed by `action=export`. Capture model-request counts immediately before/after export: export must use only deterministic local commands. Deliberately make Graphviz unavailable in a separate run; strict export must fail with an actionable error and no final failed-diagram document. Restore the override and re-export. A partial export requires an explicit request and obvious draft name/banner.
10. Open the DOCX in Word (and optionally another viewer). Inspect every page at normal size: visible contents entries and working destinations, navigation headings, chapter breaks, captions, readable diagrams, long paths, Unicode, multi-page tables with repeated headers, code and source notes. Run local preview if available and record whether all images were actually inspected. Rendering alone is not a visual pass. Keep human approval separate.
11. Compare original instruction/settings/docs/application file hashes and Git status. Only toolkit-owned installation and generated artifacts should have been written. Record completion/coverage/review/layout separately and list unresolved gaps. Retain the transcript, manifests, accepted artifacts and sample output with repository-sensitive access controls.

Expected pass record: exact environment; native-worker or bounded-fallback mode; invocation/inheritance/file-write evidence; accepted IDs before/after resume; stale rejection; coverage denominators; strict export; source review notes; all-page visual inspection; preserved originals; human approval unset. An unverified step remains explicitly unverified rather than inferred from a mock test.
